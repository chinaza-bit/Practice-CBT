Computer Architecture & Organization

A condensed revision note covering all 6 CCMAS topics — hardware & instruction sets, dataflow, CPU design, assembly programming, memory hierarchy, and I/O organization — with comparison tables and exam-style Q&A pulled straight from the course material.

1. Hardware & ISA 2. Dataflow & Control 3. CPU Design 4. Assembly Language 5. Memory Hierarchy 6. I/O Organization

1Principles of Computer Hardware & Instruction Set Architecture

What is a CPU?

The CPU (Central Processing Unit) executes instructions, performs arithmetic/logic, controls data flow, and communicates with memory and I/O devices. Its major functional units are:

  • ALU (Arithmetic and Logic Unit) — performs arithmetic (add, subtract, multiply, divide) and logic (AND, OR, NOT, comparisons).
  • Control Unit (CU) — fetches instructions from memory, decodes them, and directs the other parts.
  • Registers — small, very fast storage holding data/instructions/addresses temporarily. Key ones: MAR (Memory Address Register), MDR (Memory Data Register), ACC (Accumulator), IR (Instruction Register), PC (Program Counter).
  • Buses — communication lines: Data bus (actual data), Address bus (memory addresses), Control bus (signals like read/write, clock, interrupt).

Computer Architecture vs Computer Organization

Architecture is the blueprint (what the system does, from a programmer's view); Organization is the construction plan (how it's implemented in hardware).

Instruction Structure & Formats

An instruction has an Opcode (the operation, e.g. ADD, LOAD) and Operands (the data/addresses it works on). E.g. in ADD X1, X2, ADD is the opcode; X1 & X2 are operands.

  • Zero-address format — operands implicit, taken from the stack top (stack-based CPUs).
  • One-address format — one operand specified, the other implicit (uses an accumulator).
  • Two-address format — two operands specified.
  • Three-address format — three operands specified.

Instruction Types

  • Data Transfer — LOAD, STORE, MOVE
  • Arithmetic — ADD, SUB, MUL, DIV
  • Logical — AND, OR, NOT, XOR
  • Control — CALL, RETURN, JUMP
  • I/O — IN, OUT

Q: Explain the difference between Von Neumann and Harvard architecture.

A: Von Neumann uses a single memory and bus for instructions and data; Harvard uses separate memories and buses, allowing simultaneous access and better performance.

2Dataflow & Control Instructions

Dataflow is the pathway through which data moves inside the CPU and between the CPU, memory, and I/O. The Instruction Cycle has 3 phases:

  1. Fetch — CU gets the instruction from memory based on the Program Counter (PC).
  2. Decode — the instruction is interpreted to determine the operation and operands.
  3. Execute — the ALU or I/O system performs the operation; PC updates to the next instruction.

This cycle repeats continuously until a HALT instruction or system shutdown.

Control Instructions

  • Unconditional Jump (JMP) — forces a jump, no matter what.
  • Conditional Jump (JZ, JNZ, JC, JNC) — jumps only if a condition is met.
  • Call and Return — CALL jumps to a function (saving the return address); RETURN goes back.
  • Halt — stops execution completely until restarted.

Stack Operations

A stack is a reserved memory area that works on the LIFO principle (Last In, First Out), managed via the Stack Pointer (SP).

  • PUSH — places data on top of the stack.
  • POP — removes data from the stack into a register.

Interrupts and Their Handling

An interrupt is a signal (hardware or software) demanding the CPU's immediate attention.

  • Hardware interrupts — from external devices (keyboard, mouse).
  • Software interrupts — from running programs (e.g. divide-by-zero).
  • Maskable interrupts can be ignored (e.g. printer ready); Non-maskable ones cannot (e.g. power failure).

Interrupt handling steps: (1) CPU completes the current atomic instruction → (2) saves current state on the stack → (3) jumps to the Interrupt Service Routine (ISR) → (4) executes the ISR → (5) restores saved state and resumes the program.

Q: What are the three main stages of the instruction cycle?

A: Fetch, Decode, and Execute.

3CPU Design

CPU Design covers how the CPU is built internally, how data flows, and how control signals are generated.

Data Path

The Data Path is the collection of hardware inside the CPU that handles the movement of data between registers, ALU, memory, and I/O. Key components: Registers, ALU, Buses, and the Memory Interface.

Register Transfer Level (RTL) Design

RTL describes the flow of data between registers and the logic performed on it. Example for ADD X1, X2, X3:

TEMP <- X2 + X3   (ALU performs the addition)
X1   <- TEMP       (result stored in X1)

Hardwired vs Microprogrammed Control

FeatureHardwiredMicroprogrammed
SpeedVery fastSlower
FlexibilityDifficult to updateEasy to update
ImplementationLogic circuits (gates, flip-flops)Control memory + microcode
Best forSimple instruction sets (RISC)Complex instructions (CISC)

Hardwired advantages: high speed, efficient for simple instruction sets. Disadvantages: inflexible (new instructions need redesign), complex for large instruction sets.

Microprogrammed advantages: easy to design/update/debug, supports complex instructions. Disadvantages: slower, needs more memory.

Case Study: Intel 8085

The 8085 is an 8-bit processor with 6 general-purpose registers, using hardwired control logic. E.g. MOV A, B is implemented at RTL level as: Accumulator ← Register B. Modern processors like Intel x86 use microprogrammed control for more complex instruction decoding.

Q: Write an RTL expression for loading the sum of R1 and R2 into R3.

A: R3 ← R1 + R2

4Assembly Language Programming

Assembly language is a low-level language using mnemonics to represent machine instructions — the human-readable form of machine code. It is hardware-dependent (each CPU has its own assembly language), and one assembly instruction generally maps to one machine instruction.

Structure of an Assembly Program

  • Data section — where variables are declared (.DATA).
  • Code section — where instructions are written (.CODE).
  • Stack section — optional, for PUSH/POP (.STACK).
  • END statement — marks the end of the program.

Other assembler directives: .MODEL (memory model). Labels mark a memory location or jump target (e.g. START:).

Example Program (Add Two Numbers)

DATA SEGMENT
  NUM1 DB 05H
  NUM2 DB 03H
  SUM  DB ?
DATA ENDS

CODE SEGMENT
  MOV AL, NUM1   ; Load NUM1 into AL
  ADD AL, NUM2   ; AL = AL + NUM2
  MOV SUM, AL    ; Store result in SUM
CODE ENDS
END

MS-DOS Batch Files & Low-Level File Handling

A batch file (.BAT) is a text file of MS-DOS commands, e.g. @ECHO OFF (suppresses command echo). Low-level file handling uses INT 21H functions: 3Ch create, 3Dh open, 3Eh close, 3Fh read, 40h write.

Debugging Tools & BIOS vs DOS Interrupts

  • DEBUG — creates/tests .COM files interactively in DOS.
  • TASM/MASM — assemble (TASM file.asm) → link (TLINK file.obj) → run (file.exe). MASM is stricter; TASM supports an "ideal mode" that simplifies syntax.
  • BIOS calls (INT 10H) — hardware level, e.g. text/video display.
  • DOS calls (INT 21H) — operating-system level services, e.g. file operations, screen output.

Q: What is the purpose of a directive in Assembly Language?

A: A directive gives instructions to the assembler, not the CPU — e.g. .DATA begins the data segment.

5Memory Hierarchy

Memory hierarchy organizes memory types by speed, cost per bit, and capacity — fastest/smallest/priciest at the top, slowest/largest/cheapest at the bottom.

LevelSpeed / CostExample
RegistersFastest, smallest, most expensiveACC, PC, IR
Cache (L1/L2/L3)Fast, small, expensiveL1: 32–128KB; L2: 256KB–8MB; L3: shared, larger
Main memoryMedium speed & cost, volatileRAM
Secondary storageSlower, cheaper, largerHard disk, SSD
Tertiary storageSlowest, cheapest, largestMagnetic tapes, optical disks

Performance Metrics

AMAT (Average Memory Access Time) = Hit Time + (Miss Rate × Miss Penalty).

Virtual Memory gives programs the illusion of a large contiguous memory space while the OS maps virtual addresses to physical memory. Benefits: convenient memory management, multitasking support, apparent extra memory via disk swapping.

TLB (Translation Lookaside Buffer) — a small, fast cache for recent virtual-to-physical address translations.

Performance Optimizations

  • Reduce miss rate — use larger caches.
  • Reduce miss penalty — use hierarchical caches.
  • Reduce hit time — keep L1 cache small and simple.
  • Virtual memory — ensure the working set fits memory; maintain a high TLB hit rate.

Compiler support for cache efficiency: loop tiling/blocking, loop fusion/fission, data structure transformations, register tiling, software prefetching, cache-aware tiling, stream buffers, instruction scheduling.

6I/O Organization

I/O Organization is the design enabling the CPU to communicate and transfer data with external devices (keyboards, disks, etc.).

Components

  • I/O Module/Controller — bridges the CPU and peripherals; handles control/timing signals, processor communication, device communication & error detection.
  • System Bus — shared pathway used by CPU, memory, and I/O modules.
  • Control & Data Registers — indicate device readiness/errors, send commands, transfer data.

Methods of I/O Data Transfer

MethodHow it works
Programmed I/O (Polling)CPU continuously checks the device's status register until ready
Interrupt-driven I/ODevice sends an interrupt when ready; CPU pauses, services, resumes
Direct Memory Access (DMA)DMA controller transfers data directly between device and memory, minimal CPU involvement

Addressing Methods

  • Memory-Mapped I/O (MMIO) — devices treated like memory locations; standard load instructions apply.
  • Port-Mapped I/O (PMIO) — devices get a separate address space, accessed with special instructions (e.g. IN, OUT on x86).

Key Terms

Latency — time to complete an I/O operation (lower is better). Bandwidth (throughput) — rate of data transfer (higher is better).

Q: What does the CALL FUNC instruction do?

A: It saves the return address on the stack and jumps to the subroutine FUNC.
